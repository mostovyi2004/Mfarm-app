# CLAUDE.md — правила проєкту

Цей файл читається на початку кожної сесії Claude Code. Він — пам'ять проєкту.

## Що це за проєкт

Відкритий офлайн-застосунок для малого фермера (ОСГ, ФОП, сімейне ФГ): поля, тварини, корми, склади, переробка, гроші, документи, навігатор легалізації та вбудована база знань. Працює на Android-телефоні, планшеті, Windows і Linux без інтернету. Бізнес-дані фермера ніколи не залишають пристрій.

- Повна специфікація: `docs/spec.md`. Перед кожним кроком читай розділи, яких він стосується.
- План робіт із галочками: `docs/steps.md`.
- Мова спілкування з власником проєкту — українська. Власник — технолог з рослинництва, не програміст: пояснюй рішення простими словами.

## Стек

- Dart 3 + Flutter. Один репозиторій, пакети через pub workspaces.
- SQLite через drift. Документи PDF — пакети `pdf` + `printing`. Мапа — `flutter_map`.
- Стан екранів — Riverpod. Локалізація — ARB (gen-l10n), українська за замовчуванням.
- Тести: `dart test`, glados (property-тести), golden-тести екранів.

## Структура (цільова)

```
packages/agro_core      чисті доменні типи, операції, інваріанти (без Flutter, без I/O)
packages/agro_ledger    проведення: операція -> подія + рухи; сторно; перебудова
packages/agro_cost      собівартість, розподіли, закриття періоду
packages/agro_rules     пакет правил, ліміти ОСГ, навігатор
packages/agro_geo       геометрії полів, площі, імпорт GeoJSON/KML
packages/agro_docs      PDF-документи
packages/agro_store     SQLite (drift), міграції, резервні копії
packages/agro_adapters  онлайн-джерела (лише за згодою користувача)
apps/app                Flutter-застосунок
tools/agro_cli          консоль: перевірка, перебудова, імпорт/експорт
```

Залежності йдуть лише до ядра. `agro_core` не залежить ні від чого, крім `decimal` і `uuid`.

## Непорушні правила архітектури

1. Будь-яка зміна стану — це операція. Залишки, собівартість, поголів'я — похідні, ніколи не вводяться вручну.
2. Проведені факти не редагуються: виправлення лише через сторно.
3. Гроші — `int` у копійках. Кількості — `Decimal` з одиницею (`Quantity`). Ніколи `double` для обліку.
4. Кожен ідентифікатор — окремий тип (extension type над UUIDv7). `FieldId` не можна передати замість `PlaceId`.
5. Класи операцій — sealed class + вичерпний `switch`. Новий вид операції — запис у каталозі, а не новий клас, якщо він укладається в наявний клас.
6. Місце — один клас зі здатностями (зберігання, переробка, утримання тварин, накопичення відходів). Жодного наслідування «Склад extends Місце».
7. Бізнес-логіка лише в пакетах ядра. Екрани тільки показують дані й передають введене.
8. Відмова ядра — структурована причина (`Rejection`) з кодом і пропозиціями дій, а не виняток із текстом.
9. Жодного мережевого запиту без явної дії користувача. Бізнес-дані нікуди не надсилаються.
10. Правила закону (межі, ставки, норми) — дані в пакеті правил з датою чинності й джерелом, не константи в коді.

## Як виконується один крок

1. Власник пише номер кроку з `docs/steps.md`, наприклад «Робимо 0.5».
2. Прочитай крок, відповідні розділи `docs/spec.md` і цей файл. Коротко опиши план простими словами.
3. Спершу тест, що описує поведінку мовою господарства, потім код.
4. Запусти аналізатор і всі тести. Усе має бути зеленим.
5. Відміть крок галочкою в `docs/steps.md`.
6. Commit з повідомленням `крок 0.5: <що зроблено>`.

Правила:
- Один крок — одна тема. Нові ідеї записуй у розділ «Ідеї на потім» у `docs/steps.md`, не розширюй поточний крок.
- Якщо крок виявився завеликим, запропонуй поділити його.
- Новий екран чи функція — плюс коротка стаття довідки.
- Не вигадуй агрономічні, ветеринарні чи юридичні числа. Якщо потрібні норми чи коефіцієнти — залиш місце в довіднику й попроси власника заповнити.

## Код

- Ідентифікатори в коді — англійською. Тексти інтерфейсу — українською, лише через ARB-файли. Коментарі й документація — українською.
- Терміни домену (див. словник у `docs/spec.md`): Place — місце, Custodian — відповідальний (комірник), Item — номенклатура, Batch — партія, Operation — операція, Draft — чернетка, Posting — проведення, Reversal — сторно, Movement — рух, CostCenter — накопичувач витрат, FieldSeason — сезон поля, AnimalGroup — група тварин, Recipe — рецепт, Ration — раціон.
- Суворі правила аналізатора без вимкнень. Форматування — `dart format`.
- Невеликі файли, одна відповідальність на файл.

## Середовище

- У хмарних сесіях Dart ставиться скриптом `tools/cloud-setup.sh` (вказаний у налаштуваннях середовища claude.ai/code).
- Ядро (`agro_core` та інші пакети без Flutter) тестується в хмарі. Екрани перевіряються на телефоні через APK, який збирає GitHub Actions.
